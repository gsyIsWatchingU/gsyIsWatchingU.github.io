A · 01 · CONTEXT / OUTPUT

上下文与输出

工程问题

窗口不是越大越好。短期对话、长期记忆与 RAG 检索片段混在一起，上下文会持续腐烂；模型输出不守 Schema，改完 Prompt 也说不清是哪次改动真正生效。

解决方法

按层管理短期对话、长期记忆与检索注入，需要时才组装上下文；Schema 约束 + 解析校验 + 自纠错兜底；Prompt 版本化、可灰度，每次改动效果都能对比回滚。

Context EngineeringMemoryRAGStructured OutputJSON SchemaPrompt Versioning

A · 02 · TOOL CALLING / ORCHESTRATION

工具调用与编排

工程问题

最大敌人是空转：模型反复调用同一工具绕圈，长任务上下文持续膨胀，跨步骤的消息一致性难以保证——编排一旦失控，Agent 就从工具变成噪音。

解决方法

硬步骤上限 + 重复调用检测，Plan / Execute 拆开让模型先想再动；依赖图根因搜索、事件幂等与状态持久化，让编排可中断、可恢复、可审计——这是 Agent Harness 与普通 Prompt 工程的差异所在。

Tool CallingMCPReActLoop GuardPlan-ExecuteIdempotency
站内证据

A · 03 · RELIABILITY / GOVERNANCE

可靠执行与治理

工程问题

RAG 间接注入、高风险操作失控、重试风暴打垮下游、沙箱被绕过的代价都直接落在生产环境；简单问题烧在贵模型上则是另一种静默的成本失控。

解决方法

防注入 + 按风险分级审批；重试加并发上限防 storm；高风险操作跑在沙箱里；权限门禁与执行审计兜底；大小模型按任务路由、语义缓存设 TTL、Token 预算硬限制。

Injection DefenseApproval GateSandboxCircuit BreakerModel RoutingToken Budget
站内证据

A · 04 · EVAL / OBSERVABILITY

评测与观测

工程问题

非确定性 bug 难以复现，模型静默漂移；线上失败 case 如果不回流，评测集和真实问题会越离越远，回归变成走过场。

解决方法

线上失败 case 反哺评测集；全链路 Trace 复现非确定性 bug；LLM-as-Judge 做批量回归，定期冒烟 + 漂移告警拦截模型静默变化。

B · 02 · SERVICE / DATA MODELING

服务与数据建模

工程问题

AI 生成的数据要可修正、可重跑、可追溯，直接把模型输出写库会在下游变成脏数据；缓存里混进概率性结果会让查询结果时真时假。

解决方法

用状态机区分「生成中 / 已确认 / 已修正」，写入带延迟保存与版本冲突保护；确定性查询与概率性生成分开缓存，按语义设 TTL。

PostgreSQLRedis缓存策略State Machine
站内证据

B · 03 · REAL-TIME / ASYNC

实时与异步系统

工程问题

流式输出、长任务、多人实时协作同步，处理不好就是页面卡死、消息堆积或状态错乱；AI 生成速度可能快过客户端渲染，不能无脑推送。

解决方法

流式输出用 SSE 就够；长任务丢队列异步跑并推进度；背压控制让生产与消费速度匹配；协同与业务通知走独立通道，权限变化实时收敛。

SSEWebSocketBullMQBackpressureYjs
站内证据

B · 04 · ARCHITECTURE / CI / CD

架构与持续交付

工程问题

模型版本与代码一起变化，出问题要能一起回滚；跨仓改动如果失控，稳定性问题会在多个平台反复出现。

解决方法

确定性代码单测全覆盖，模块边界控制变化范围；模型版本与代码一起版本化，可整体回滚；跨仓改动统一盘点、分级排期、合并上线。
